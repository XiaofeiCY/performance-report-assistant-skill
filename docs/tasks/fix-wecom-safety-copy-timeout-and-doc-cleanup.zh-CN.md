# 任务：收缩企微自动化安全边界、修复复制/超时策略并清理项目约束

## 背景

随着企业微信智能总结采集需求不断扩展，当前实现已经出现补丁叠加和历史约束混杂问题。最新审查发现，代码中仍残留已被否定的纵向扫描、超时后继续复制、激进复制 fallback 等行为。

本任务以第一性原理重新收缩边界：企微采集器的首要目标不是“尽可能自动”，而是“在用户监督下、只在可验证 UI 状态内、安全采集本次智能总结结果”。任何不确定状态都应停止并保留诊断，而不是继续点击、滚动、右键或全选复制。

## 用户最新决策

1. 左侧纵向扫描思路错误。企业微信窗口可任意伸缩，不能用一串绝对坐标或纵向扫描找入口，偏差概率很大。
2. 智能总结耗时不可固定。触发总结后，分析时长取决于提示词和聊天内容，不能只依赖固定超时。
3. 复制结果不严谨。总结完成后操作按钮位于页面底部；窗口未完整显示、内容过长或有滚动条时，截图可能扫不到“复制”按钮。
4. 需要交叉验证，保证最基础操作正常。
5. `CLAUDE.md`、`AGENT.md` 已由用户手动删除，因为此前文件用途被滥用；后续不要再恢复这两个文件，统一以 `AGENTS.md` 为项目入口。
6. 当前需要整理项目文档和任务入口。
7. 过期任务需要整理归档。
8. 本地运行产物需要整理。
9. Excel 后缀兼容需要处理。
10. README/对外说明需要整理，反映企微能力真实边界。

## 目标

完成一次“收缩而不是继续扩张”的修复：

- 移除企微入口纵向扫描和多点试探。
- 改造智能总结等待策略，避免固定超时误判。
- 重新设计结果复制策略，解决按钮在底部、窗口不完整、结果过长、滚动条遮挡等问题。
- 为企微核心流程建立最小交叉验证。
- 清理文档入口，让当前约束唯一、明确、可派发。
- 增加 Excel 文件后缀兼容策略，至少明确支持/拒绝边界，避免误伤宏模板。

## 必须修复：企微入口定位

### 禁止行为

- 禁止沿企业微信左侧菜单纵向扫描。
- 禁止多点试探点击未知入口。
- 禁止依赖固定绝对坐标作为主要入口定位方式。
- 禁止因为“窗口高度接近某个值”就默认点击某个入口。

### 允许行为

入口打开只允许以下有限策略：

1. UI Automation 精确找到名称/AutomationId 为“智能总结”的可见控件。
2. OCR 在明确限定的企业微信窗口截图内识别完整“智能总结”文字，并点击该文字框中心。
3. 单个 probe 校准点只能作为临时兼容 fallback，并且必须满足：
   - 用户/文档明确标注为不稳定；
   - 点击前后都有页面分类；
   - 失败后立即停止；
   - 不得扩展为多点扫描。

如果窗口缩放导致入口不可识别，脚本应失败并保存截图/OCR，而不是继续猜。

## 必须修复：智能总结等待策略

固定 `--timeout` 只能作为总安全上限，不能作为“生成完成”的主要判断。

建议状态：

```text
submitted
-> generating
-> result_detected
-> copy_available
-> copied
-> timeout_or_stalled
```

完成判断应优先依赖可观察 UI 信号：

- “开始总结”按钮消失或变成不可操作状态。
- 页面出现结果正文区域。
- 页面出现底部结果操作区，例如“新建文档 / 发送邮件 / 复制”。
- UIA 能识别到结果操作按钮。
- OCR 文本量稳定增长后停止变化一段时间。

建议增加两个超时概念：

- `--max-wait-seconds`：硬上限，防止无限等待。
- `--stable-seconds`：结果文本或页面状态连续稳定多少秒后认为可尝试复制。

等待期间必须输出心跳，例如：

```text
企微采集进度：智能总结生成中，已等待 45 秒；当前检测到结果文本增长，继续等待。
企微采集进度：结果文本 20 秒未变化，准备进入复制阶段。
```

如果达到硬上限：

- 只有在能确认当前仍是智能总结结果页，并且存在可复制结果时，才允许进入复制阶段。
- 否则停止并保存截图/OCR，不得继续不确定复制。

## 必须修复：结果复制策略

当前问题：

- “复制”按钮可能在页面底部。
- 企业微信窗口未完整显示时，截图可能截不到底部按钮。
- 结果内容过长时，页面存在滚动条，按钮可能需要滚到底部才出现。
- OCR 可能识别不到小字号按钮。

推荐优先级：

1. UI Automation 查找“复制”按钮或底部结果操作区。
2. 如果 UIA 无法定位，先确认结果页，再在智能总结内容区域内执行有限滚动到底部。
3. 滚动后重新截图/OCR 分类，确认仍在智能总结结果页。
4. OCR 查找“复制”按钮。
5. 如果仍找不到“复制”按钮，停止并提示用户手动复制或使用 `--manual-input`。

禁止行为：

- 不得在未确认结果页时右键菜单复制。
- 不得对未知区域执行 `Ctrl+A / Ctrl+C`。
- 不得用多个固定坐标猜“复制”按钮。
- 不得复制历史结果页作为本次结果。

允许的滚动必须满足：

- 仅在确认智能总结结果页后执行。
- 滚动范围限定在智能总结内容区域内。
- 每次滚动后重新验证页面仍是智能总结。
- 滚动次数有上限。
- 失败时保存滚动前后截图/OCR。

- 页面分类函数可用保存的 OCR 文本或截图 fixture 验证：
  - 主聊天页；
  - 智能总结输入页；
  - 智能总结历史结果页；
  - 智能总结结果页/复制可用页。

4. 实机验证必须由用户监督：

- 企业微信在后台时，脚本能尝试前台恢复。
- 企业微信主页面无法识别入口时，脚本停止，不纵向扫描。
- 智能总结生成时间较长时，脚本心跳等待，不误判卡死。
- 结果过长时，脚本能在结果页内有限滚动查找复制按钮；找不到则停止，不全选复制未知区域。

## Excel 后缀兼容要求

当前 `fill_excel_template.py` 主要面向 `.xlsx`。需要补齐文件后缀策略：

- `.xlsx`：继续支持。
- `.xlsm`：必须显式支持宏保留，使用 `openpyxl.load_workbook(..., keep_vba=True)` 并输出 `.xlsm`；如果无法保证宏保留，应拒绝并给出清晰提示。
- `.xltx` / `.xltm`：作为模板文件时，应复制并输出为用户指定的 `.xlsx` / `.xlsm`，同时说明宏模板限制。
- `.xls`：不支持直接写入，应清晰提示需先另存为 `.xlsx` 或提供转换流程。
- 输出后缀必须与模板能力一致，不允许把含宏模板静默保存成丢宏的 `.xlsx`。

验收：

- `.xlsx` 回归通过。
- `.xlsm` 至少有保宏测试或明确拒绝逻辑。
- 不支持格式有可读错误，不是堆栈崩溃。

## 验收标准

- 左侧纵向扫描被移除。
- 入口定位只依赖 UIA/OCR 精确命中和最多一个明确标注的不稳定 fallback。

- 复制流程能处理按钮在底部、窗口不完整显示、长结果滚动等情况；无法处理时安全失败。
- 不再使用右键菜单、固定坐标列表、未知区域 `Ctrl+A/Ctrl+C` 作为默认复制 fallback。
- 粘贴 prompt 前确认输入页和输入区域。
- 每个危险动作前确认企业微信前台和页面状态。
- 文档中没有把历史任务当当前任务。
- `AGENTS.md`、`docs/status.md`、README、企微参考文档彼此一致。
- Excel 后缀兼容或拒绝策略明确且经过最小验证。
