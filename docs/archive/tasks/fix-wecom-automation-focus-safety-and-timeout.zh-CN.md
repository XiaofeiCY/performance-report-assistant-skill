# 任务：修复企微自动化焦点安全、错误点击和长时间卡住问题

## 一、背景

用户测试 `collect_wecom_smart_summary.py` 后发现自动化体验不通过：

- 脚本没有把企业微信窗口拉起到最前。
- 提示词被输入到了当前 Codex 窗口的输入框里，而不是企业微信智能总结。
- 脚本随后长时间卡住，几分钟没有有效反馈或退出。

这说明当前实现存在严重的桌面自动化安全问题：在没有确认目标窗口已聚焦、目标界面已识别成功之前，就发送了粘贴/点击操作。

## 二、验收结论

当前实现不合格，需要返工。

问题不是单一 OCR 识别失败，而是整条自动化链路缺少安全护栏：

1. 未可靠拉起企业微信到前台。
2. 未在粘贴前确认前台窗口确实是企业微信。
3. 未在粘贴前确认当前可见界面确实是智能总结界面。
4. 失败后仍可能继续向错误窗口发送输入。
5. 等待阶段缺少强制超时、心跳进度和阶段性失败退出。

## 三、关键问题定位

### 1. 前台窗口确认不足

文件：

```text
performance-report-assistant/scripts/collect_wecom_smart_summary.py
```

相关位置：

- `_focus_window()`：尝试 `SetForegroundWindow`、`BringWindowToTop` 和 `AttachThreadInput`。
- `run_automation()`：如果 `_focus_window()` 返回成功，就继续后续点击和粘贴。

问题：

- Windows 前台激活可能被系统限制。
- 即使 `_focus_window()` 看似成功，也可能不是预期可操作区域。
- 后续每次点击、粘贴前没有重新验证当前前台窗口。
- 没有确认 `GetForegroundWindow()` 的 class/title/进程属于企业微信。

### 2. 错误窗口输入风险

相关位置：

```python
pyperclip.copy(prompt)
with interception.hold_key("ctrl"):
    interception.press("v")
```

问题：

- 粘贴前没有做最后一道安全检查。
- 如果当前焦点仍在 Codex 输入框，提示词会被粘贴到 Codex。
- 这是不可接受的自动化行为。

必须改为：

- 粘贴前强制检查前台窗口。
- 强制截图并 OCR/特征确认当前是企业微信智能总结界面。
- 任一检查失败，立即停止，不得发送键盘输入。

### 3. 坐标点击不可靠

当前脚本使用：

```python
interception.move_to(active_rect.left + 400, active_rect.top + 100)
interception.click(button="left")
```

问题：

- 这是固定偏移坐标，不保证是输入框。
- 如果窗口没有置顶，点击的是其他应用同位置。
- 如果布局变化，会点错位置。

必须改为：

- 优先 OCR/UIA 定位输入框或可编辑区域。
- 固定坐标只能作为最后 fallback，并且必须在前台窗口和界面识别都成功后才能用。
- 每次 fallback 坐标点击前后都要验证状态。

### 4. 等待阶段体验差

用户反馈“卡住好几分钟没有反应”。

当前脚本虽然有 `--timeout`，但体验上仍不足：

- OCR 初始化可能耗时长，没有阶段性提示。
- 轮询期间只有 debug 模式才输出 OCR 摘要。
- 非 debug 模式下长时间沉默。
- 失败后可能仍继续尝试复制当前结果，给用户造成卡死感。

必须改为：

- OCR 初始化前后都输出进度。
- 每轮或每隔固定时间输出心跳进度。
- 每个阶段设置明确最大耗时。
- 超时后必须清楚退出，不得继续执行不确定点击。

## 四、目标

修复后，脚本必须满足：

- 没有确认企业微信前台时，不得点击或粘贴。
- 没有确认智能总结界面时，不得粘贴 prompt。
- 任何输入动作前必须有目标窗口安全检查。
- 如果无法拉起企业微信，必须快速失败并提示用户手动点击企微或使用手动模式。
- 不允许再把 prompt 粘贴到 Codex、终端、浏览器或其他非企业微信窗口。
- 长耗时阶段必须持续输出进度，不能让用户以为卡死。

## 五、必须实现的行为

### 1. 增加目标窗口安全检查

新增函数建议：

```text
get_foreground_window_info()
is_wecom_window(hwnd)
assert_wecom_foreground(stage)
assert_smart_summary_visible(stage)
safe_click(x, y, stage)
safe_paste_text(text, stage)
```

每次执行以下动作前，必须调用安全检查：

- 鼠标点击；
- 粘贴 prompt；
- Ctrl+A；
- Ctrl+C；
- 点击复制；
- fallback 坐标操作。

如果检查失败：

```text
企微采集失败：[stage] 前台窗口不是企业微信，已停止自动化，避免误操作其他窗口。
```

并立即退出，不能继续。

### 2. 聚焦企业微信必须可验证

拉起企业微信后，需要验证：

- `GetForegroundWindow()` 对应窗口或其父窗口属于企业微信；
- class/title/process 能证明是企业微信；
- 截图区域可见且尺寸正常；
- OCR 或窗口层级能识别到企业微信相关界面。

如果验证失败，不要点击当前屏幕坐标。

### 3. 智能总结界面必须可验证

进入智能总结后，需要确认：

- OCR 识别到“智能总结”或相关关键文本；
- 或识别到输入区和“开始总结”按钮；
- 或 UIA 控件层级确认处于智能总结界面。

没有确认前，不得粘贴 prompt。

### 4. 粘贴前必须二次确认

在执行：

```python
pyperclip.copy(prompt)
Ctrl+V
```

之前，必须完成：

- 前台窗口是企业微信；
- 智能总结界面可见；
- 输入区域已被安全定位并点击；
- 点击后前台窗口仍是企业微信。

任一失败都要停止。

### 5. 入口打开失败要快速失败

如果无法自行打开智能总结入口：

- 不要继续尝试粘贴；
- 不要点固定位置；
- 不要卡住；
- 输出明确失败原因和下一步：

```text
企微采集失败：未能确认智能总结入口已打开。
我已停止自动化，避免把提示词输入到其他窗口。
你可以手动打开智能总结后重试，或使用 --manual-input。
```

### 6. 进度心跳和阶段超时

必须增加非 debug 模式下的进度反馈。

建议：

- OCR 初始化阶段：

```text
企微采集进度：正在初始化 OCR，首次加载可能需要几十秒。
企微采集进度：OCR 初始化完成。
```

- 等待总结阶段每 10 秒输出一次：

```text
企微采集进度：等待总结生成中，已等待 30/120 秒。
```

- 每个关键阶段都有最大耗时：
  - 查找窗口；
  - 拉起窗口；
  - 打开入口；
  - 等待界面；
  - 等待总结；
  - 复制结果。

超过阶段耗时必须退出并说明原因。

### 7. 默认不继续复制“当前结果”

当前逻辑在等待超时后仍尝试复制当前结果：

```python
if not found_result:
    print("企微采集进度：等待超时，将尝试复制当前结果。")
```

这可能在界面未确认时继续误操作。

建议改为：

- 仅当仍确认前台是企业微信且智能总结界面可见，并且 OCR 识别到结果区域或复制按钮时，才允许复制。
- 否则直接失败，不做不确定复制。
