# 任务：接入多来源材料采集流程与企微智能总结采集

## 一、背景

`performance-report-assistant` 目前已经支持从代码仓库、周报草稿、模板、旧报告参考等材料中整理中文工作汇报。用户现在希望补充一种新的材料来源：企业微信 Windows 客户端里的“智能总结”。

这个需求不是单纯新增一个脚本，而是要让 skill 在“收集材料 / 采集证据”阶段具备多来源编排能力：

- 用户只提供仓库地址时，只做仓库数据采集。
- 用户提供仓库地址和 Word 文档时，分别采集仓库数据和 Word 文档内容。
- 用户要求进行企微智能总结采集时，再进入企微采集流程。
- 多个来源可以同时存在，但每个来源要独立执行、独立记录状态。
- 任意一个来源失败，不能影响其他来源继续采集。

企微智能总结采集器的具体实现要求，必须参考并执行：

```text
E:\work\performance-report-assistant-skill\docs\claude-task-implement-wecom-smart-summary-collector-only.md
```

该文档是采集器本体实现任务。本任务是在它的基础上，补齐 skill 主流程如何识别、确认、执行、汇总多来源材料。

## 二、用户需求复述

用户希望 skill 在需要材料时，不再只笼统要求“仓库路径、周报草稿”等，而是能识别用户提供或选择的一个或多个材料来源，并一步步执行。

典型场景：

1. 用户只提供一些仓库地址：
   - 只做仓库数据采集；
   - 不触发 Word、企微等无关流程。

2. 用户提供仓库地址和 Word 文档：
   - 仓库数据采集和 Word 文档读取都要执行；
   - 两者独立记录成功或失败。

3. 用户要求进行企微智能总结采集：
   - 先问用户要采集什么内容；
   - 根据前面确认的报告周期，给出动态默认提示词；
   - 执行前确认企业微信登录、用户在电脑前、是否允许桌面自动化等前置条件；
   - 用户明确肯定后才执行；
   - 执行过程中要及时同步进度；
   - 失败时提供手动输入或重试方案，不影响其他材料来源。

4. 多个材料来源并行或串行执行时：
   - 一个来源失败不能阻塞其他来源；
   - 最终汇总时要清楚列出每个来源的状态、输出路径、失败原因和是否可继续生成报告。

## 三、目标

更新 skill，使其具备以下能力：

- 将材料来源建模为可独立执行的 evidence source。
- 支持多来源材料采集：代码仓库、Word 文档、周报草稿、旧报告结构参考、企微智能总结、其他文本材料。
- 在企微智能总结采集前完成采集目标确认、默认 prompt 生成、前置条件确认和用户授权确认。
- 在企微采集和其他长耗时采集过程中实时同步状态。
- 在任一来源失败时记录失败，但不中断其他来源。
- 在生成报告前展示材料采集汇总，让用户确认是否基于现有材料继续。

## 五、多来源材料编排规则

### 1. 材料来源分类

skill 应该能区分以下来源：

- `repository`：本地仓库路径或 Git URL。
- `word_document`：Word 文档。
- `weekly_draft`：用户粘贴或提供的周报草稿。
- `previous_report_reference`：旧周报/旧绩效，仅作为结构、格式、口吻参考。
- `wecom_smart_summary`：企业微信智能总结采集结果。
- `free_text`：用户直接提供的其他文字材料。
- `template`：Excel/Word/PPT/Markdown 固定模板。

### 2. 每个来源必须有独立状态

每个来源至少记录：

- 来源类型；
- 用户提供的信息；
- 是否需要执行采集；
- 当前状态：`pending` / `confirming` / `running` / `succeeded` / `failed` / `skipped` / `needs_user_input`；
- 输出文件路径或采集结果位置；
- 失败原因；
- 是否可用作当前周期证据；
- 是否只是结构参考。

### 3. 单个来源失败不能影响其他来源

如果某个来源失败：

- 记录失败状态和原因；
- 继续处理其他来源；
- 不要清空已成功采集的材料；
- 不要把失败来源静默忽略；
- 不要因为企微失败就终止仓库统计或 Word 读取；
- 不要因为某个仓库失败就终止其他仓库统计。

示例提示：

```text
企微智能总结采集失败：未找到智能总结窗口。
我会保留这个失败状态，并继续处理已提供的仓库和文档材料。
稍后你可以选择重试企微采集、改用手动粘贴，或先基于现有材料继续。
```

### 4. 生成报告前必须汇总来源状态

在写报告或填模板前，必须向用户展示：

```text
当前材料采集状态：
- 仓库 A：成功，输出 outputs/repo_a_commits.md
- 仓库 B：失败，原因：认证失败
- Word 文档：成功，已读取
- 旧周报：仅参考结构，不复用内容
- 企微智能总结：失败，原因：未找到智能总结窗口

是否基于已成功材料继续生成？你也可以选择重试失败来源或补充手动材料。
```

只有当失败来源可能影响报告质量时，必须让用户选择：

- 继续使用已有材料；
- 重试失败来源；
- 改用手动输入；
- 暂停。

## 六、企微智能总结采集流程要求

### 1. 仅在用户要求时触发

不要自动触发企微采集。

只有当用户明确说：

- “采集企微智能总结”；
- “从企业微信智能总结提取”；
- “帮我总结企微聊天记录”；
- “用企微智能总结作为材料”；

或类似表达时，才进入企微采集流程。

### 2. 执行前先确认采集内容

进入企微采集流程后，先问用户需要采集什么内容。

如果前面已经确认了报告周期，则给出动态默认提示词，时间范围必须来自当前上下文，不得写死。

默认提示词示例：

```text
帮我总结 [YYYY-MM-DD] 到 [YYYY-MM-DD] 内的聊天记录，哪些人、哪些群找到我，梳理我在每次对话中产出的工作内容有什么。只列出真实发生的工作事项，不要夸大，不要把讨论中的计划写成已完成。
```

如果是月度绩效，默认提示可以调整为：

```text
帮我总结 [YYYY-MM-DD] 到 [YYYY-MM-DD] 内的聊天记录，哪些人、哪些群找到我，梳理我在每次对话中产出的工作内容、协调事项、问题处理、风险跟进和交付结果。只列出真实发生的事项，保留可核验的上下文。
```

用户可以：

- 直接确认使用默认提示词；
- 修改提示词；
- 提供自己的 prompt 文件或文本。

### 3. 企微自动化执行前必须确认前置条件

在运行任何桌面自动化前，必须展示确认清单，并等待用户明确肯定。

确认项至少包括：

- 当前运行环境是 Windows。
- 企业微信 Windows 客户端已登录。
- 用户已打开目标聊天、目标群、或目标范围所在界面。
- 如果脚本要求用户先进入智能总结界面，用户已进入。
- 用户正在电脑前监督。
- 用户允许脚本使用截图、OCR、Interception 输入、剪贴板读取。
- 脚本不会读取数据库、不会逆向客户端、不会发送消息、不会删除/转发/编辑消息。
- 如果自动化失败，是否允许改用手动输入模式。
- 输出 Markdown/JSON 文件路径。

建议提示：

```text
执行企微智能总结采集前，请确认：
- 你已登录企业微信 Windows 客户端；
- 已打开目标聊天/群/范围，或已进入“智能总结”界面；
- 你正在电脑前监督；
- 允许脚本使用截图、OCR、Interception 输入和剪贴板读取；
- 脚本不会发送、删除、编辑或转发任何消息；
- 如果自动化失败，可以改用手动粘贴智能总结结果；
- 输出路径为：[path]。

确认无误后我再执行。请明确回复“确认执行企微采集”。
```

未收到明确确认前，不得执行企微自动化。

### 4. 执行过程必须同步进度

企微采集可能耗时较长。执行时必须分阶段反馈进度，例如：

```text
企微采集进度：正在检查运行环境和依赖。
企微采集进度：正在定位企业微信窗口。
企微采集进度：正在识别智能总结窗口。
企微采集进度：正在粘贴采集提示词。
企微采集进度：已点击开始总结，正在等待结果生成。
企微采集进度：检测到复制按钮，正在读取剪贴板。
企微采集完成：结果已保存到 outputs/wecom_summary.md。
```

如果失败，也要说明阶段和原因：

```text
企微采集失败：OCR 未识别到“开始总结”按钮。
我已停止自动化操作，不会继续乱点。你可以调整窗口后重试，或改用手动输入模式。
```

### 5. 企微结果必须标记为待确认证据

企微智能总结结果不能直接当成事实。

输出状态应标记为：

```text
Status: needs_user_confirmation
```

报告生成前应提醒用户确认：

```text
企微智能总结是聊天记录摘要，可能遗漏或误解上下文。我会把它作为待确认证据使用，不会直接把讨论、计划或风险提醒写成已完成工作。
```

- 不处理登录、验证码、安全弹窗。
